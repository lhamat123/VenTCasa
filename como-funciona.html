LLAVE en Mano
cómo funciona y cómo protegerla

Esta guía explica, sin tecnicismos, qué hace la app por dentro y los pasos para dejarla configurada de forma que solo tú (el administrador) puedas agregar, editar o borrar propiedades — cualquier otra persona solo puede mirar el catálogo.

1 Qué hace la app

Es un catálogo de inmuebles de una sola página. Cualquier visitante puede buscar, filtrar y ver el detalle de cada propiedad — nadie necesita cuenta ni contraseña para eso.

🔍

Búsqueda y filtros

Por nombre, tipo, precio, comodidades, locales y estado de la documentación.

🗂️

Vista grid o lista

Con paginación (12 propiedades por página) para que no se sature con muchos inmuebles.

⭐

Favoritos

Cada visitante puede marcar propiedades; se guarda en su propio navegador.

🖼️

Galería con zoom

Fotos principales y galería por propiedad, con visor ampliado.

💬

Contacto directo

Botón de WhatsApp directo al número del dueño de cada inmueble.

🔲

QR para compartir

Cada propiedad genera un código QR que abre directamente su ficha.

2 Dónde viven los datos

No hay una base de datos tradicional. Las propiedades se guardan en un archivo (data.json) dentro de tu propio repositorio de GitHub, y las fotos se sirven desde ahí mismo. Es gratis y no depende de ningún servidor que tengas que mantener.

La parte importante es cómo se escribe ese archivo cuando agregas o editas una propiedad — de eso trata el resto de esta guía.

3 Cómo se protege la edición

Antes, la contraseña de administrador y el token de GitHub vivían directamente en el código de la página — cualquiera que supiera mirar el código fuente podía copiarlos y editar tu catálogo sin permiso. Ahora el flujo es distinto:

🧑Visitantesolo lectura
ve el catálogo→
🗃️GitHubdata.json + fotos
🔐Administradorsolo con contraseña
pide guardar→
🛡️Workerguarda el token
escribe→
🗃️GitHubdata.json + fotos

El token de GitHub nunca llega al navegador — queda guardado únicamente dentro de Cloudflare (el servicio donde vive el Worker). Cuando entras al panel de administración, la app solo te pide tu contraseña; si es correcta, el Worker se encarga de hablar con GitHub por ti.

✅

Resultado: aunque alguien copie el código completo de tu página (`Ver código fuente` del navegador), no va a encontrar ningún token ahí — no hay forma de editar tu catálogo sin tu contraseña.

4 Configurarlo paso a paso

Esto se hace una sola vez. Necesitas una cuenta gratuita de Cloudflare y tener Node.js instalado en tu computadora.

Instala la herramienta de Cloudflare (wrangler)

Desde una terminal:

npm install -g wrangler
wrangler login

El segundo comando abre el navegador para conectar la herramienta con tu cuenta de Cloudflare.

Crea un token de GitHub solo para este proyecto

En GitHub: Settings → Developer settings → Fine-grained tokens → Generate new token.

Elige "Only select repositories" y selecciona únicamente el repo Vhome. En permisos, dale "Contents: Read and write" y nada más. Copia el token — solo se muestra una vez.

⚠️

Este token es la llave real. A partir de este paso solo va a vivir dentro de Cloudflare — no lo pegues en ningún archivo del proyecto ni lo compartas por chat o correo.

Publica el Worker

Desde la carpeta worker/ del proyecto:

wrangler deploy

Te va a dar una URL parecida a https://llave-en-mano-api.tu-subdominio.workers.dev. Guárdala, la usas en el paso 5.

Guarda tus secretos en Cloudflare

Cada comando te va a pedir el valor por separado (no queda escrito en tu historial de terminal):

wrangler secret put GITHUB_TOKEN
wrangler secret put APP_PASS
wrangler secret put SESSION_SECRET
  • GITHUB_TOKEN → el token del paso 2
  • APP_PASS → la contraseña con la que vas a entrar al panel
  • SESSION_SECRET → cualquier cadena larga y aleatoria (ej. openssl rand -hex 32)

Conecta la página con el Worker

En index.html (o script.js si ya lo separaste), busca:

const WORKER_URL = 'https://llave-en-mano-api.TU-SUBDOMINIO.workers.dev';

y reemplaza esa URL por la real que te dio wrangler deploy.

(Recomendado) Limita quién puede llamar al Worker

En worker/wrangler.toml, cambia ALLOWED_ORIGIN = "*" por el dominio real donde publiques la página, y vuelve a correr wrangler deploy. Así, aunque alguien copie tu página completa, su copia no va a poder guardar cambios en tu repo.

5 Cómo usarlo desde el día a día

Una vez configurado, el uso diario es simple:

  • Cualquier visitante entra al link de la página y ve el catálogo — sin login.
  • Tú tocas el candado 🔒 arriba a la derecha, escribes tu contraseña y entras como editor.
  • Mientras estás dentro, aparecen los botones de agregar, editar y borrar propiedades.
  • Tu sesión de administrador dura 6 horas o hasta que cierres sesión — después hay que volver a poner la contraseña.
  • Si alguien más necesita editar, compártele solo la contraseña — nunca hace falta compartir ningún token.
